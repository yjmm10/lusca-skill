# 页面架构与动效

三页分工：落地页负责理解与转化，数据页负责事实与核验，关于页负责主体介绍与边界说明。信息只在一处展开，跨页用链接衔接，不重复整段文案。

## 落地页

推荐顺序：

1. Hero：一句主张 + 一句解释 + 一个明确 CTA；背景克制，不抢正文。
2. 产品预览：用 `gallery` 的渲染图/截图；可切换 2-4 张，默认不自动轮播。
3. 核心指标：从 `highlights.metrics` 取 3-6 个，按重要性排；每张卡显示来源与时间。
4. 最新动态：从 `highlights.latest` 取前 3 条，显示日期、标题、摘要和链接。
5. 能力/场景：从 `highlights.features` 取 3-6 个，按用户决策路径排列。
6. FAQ：只展示数据中存在的问题与答案。
7. CTA：回到数据页或联系入口。

动效：进场渐显、数字轻动、预览切换、主题切换过渡即可；尊重 `prefers-reduced-motion`。不要让动画成为理解内容的必要条件。

## 数据页

- 顶部写清“数据更新时间 / 统计口径 / 来源说明”。
- 指标表格支持排序、搜索、按标签筛选；无 JS 时也应能读到完整表格。
- 移动端把宽表转卡片，优先显示指标名、数值、周期。
- 空状态写“为什么为空”和“怎么恢复”，错误状态写可联系入口或来源链接。
- 数据来源与方法论链接到原始出处，不把本站自己当来源。

## 关于页

- 产品：为什么存在、解决什么问题、适合谁、不适合谁。
- 作者/团队：真实名称、角色、简介、可核验链接。
- 免责声明：数据时效、非建议声明、商标/版权归属、第三方链接责任边界；写得具体，不用模板腔。
- 结尾不放“AI 生成/仅供参考/欢迎指正”式尾巴。

## 组件边界

- `BaseLayout`：head 元信息、结构化数据、主题初始化、页头页脚、语言切换。
- `MetricCard`：单一指标展示，不负责排序。
- `DataTable`：完整数据呈现与筛选，不负责派生摘要。
- `LatestStrip`：只接收 `highlights.latest`。
- `ProductPreview`：只接收 `gallery`，负责预览切换。
- `ThemeToggle`：只负责主题状态，不处理业务数据。

单一职责让后续替换组件库时不牵动数据逻辑。
