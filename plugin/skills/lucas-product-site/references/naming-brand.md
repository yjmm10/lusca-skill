# 命名与品牌

目标：得到一个短、可讲、能与 logo 互相解释的产品名。好名字减少解释成本，也让域名、页面标题和结构化数据里的实体更稳定。

## 工作流

1. 提取产品本质：一句话说清它做什么、给谁、气质是什么（可靠/锋利/温和/探索/秩序）。
2. 发散 5-10 个候选：优先一个词，避免多个英文单词用连字符拼接。过长或太泛时，换成同特质的神话、天文、器物、地理或东方文化意象。
3. 初筛 2-3 个：按读音、拼写、记忆、语义贴合、中文/英文可读性打分。
4. 做基础可用性检查：GitHub 仓库名、npm 包名、主域名、`site:` 搜索歧义。结果只作为线索，商标与法律可用性提示用户人工核验。
5. 让用户确认最终名；没有确认前只写“候选名”，不要宣称定稿。
6. 写 `docs/brand.md`：名字、含义、气质、候选落选原因、基础检查结果、logo 解释。

## 命名启发

- 可靠/基础设施：Aegis、Atlas、Vault、Keystone、磐石、玄圭。
- 速度/洞察：Aether、Lumen、Pulse、Comet、流萤、青鸾。
- 工艺/创造：Hephaestus、Forge、Loom、Anvil、匠星、鲁班。
- 数据/秩序：Canvas、Prism、Index、Ledger、衡镜、星槎。

这些只是意象起点，不代表可用性；真正采用前必须按产品语义与检查结果判断。

## Logo 一致性

- 结构分层：主符号（图形隐喻）+ 辅助元素（轨道/节点/光斑/描边等）+ 可选字标；单一几何形或纯文字不算合格 logo。
- 主符号必须能从名字含义讲出来，例如 Aether 用轨道 + 星芒（空中介质/星光），Atlas 用承托结构，青鸾用鸟翼抽象。
- 允许克制的渐变与内发光增加层次，但避免复杂纹理；缩小到 32px 仍能认出主符号。
- 使用设计 token 里的品牌色与中性色，深浅主题下都可读。
- 同时交付 `public/logo.svg`、`public/logo.png`（至少 512×512）、`public/favicon.svg`，并生成 OG 分享图（1200×630，徽章 + 内容剪影）。
- SVG 必须简洁、可编辑、无外链字体；PNG 由 SVG 渲染，不单独手绘出第二套视觉；渲染不可用时用脚本以相同几何直接绘制光栅版。

## 交付格式

```markdown
## 候选名
- Aether：轻量、空中介质，契合“让数据透明呈现”；GitHub/npm 基础检查结果：...
- 青鸾：东方意象，传达快速传递信息；基础检查结果：...

## 推荐
名称：...
理由：...
需要用户确认：域名、商标、已有品牌冲突。
```
