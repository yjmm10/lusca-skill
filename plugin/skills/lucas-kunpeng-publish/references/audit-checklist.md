# audit-checklist — 审计清单

前五维对应鲲鹏发布要求五条（可判合规 / 不合规），第六维是生态红线（下线风险）。每个问题定位到**行号或小节**，标严重度（高 = 不合规 / 下线风险，中 = 质量风险，低 = 建议）。

## 一、正文外部链接（要求 1）

- 扫描范围 = **正文**（frontmatter 之后全部内容，含文末参考来源节、图注）；frontmatter 不随发布，其中 `sources` 的 URL 不算违规、反而保留作查证底账
- 扫 URL 与 markdown 链接：正文、参考来源节、图注——**发现即高严重度**
- 改法：出处改文字标注（文档名 · 版本/章节）；正文参考来源节保留条目、去掉 URL（frontmatter 已有对应 url 则直接删）；正文中"参考某文档第 X 节"句式替代超链接
- 注意变体：脚注链接、图片外链、`<https://...>` 裸 URL 同样算

## 二、图片（要求 2）

- 扫 `![...](...)` 与 HTML `<img>`：**发现即高严重度**，删除（frontmatter 的 cover 字段一并清）
- 架构 / 流程内容的替代表达：文字层次描述 + 表格；**不建议** mermaid（平台编辑器不保证渲染）
- 删图后检查上下文引用（"如下图所示"→ 改为指向文字描述或表格）

## 三、表述专业严谨（要求 3）

- 口语 / 比喻 / 打趣 / 反问（"咱们""秒表""是不是很简单？"）→ 中严重度，逐处改陈述句
- 绝对化与营销化（"一定""彻底解决""革命性"）→ 中严重度
- 结论无出处：改为文字标注来源或降格为"据某文档"；未验证断言标 `(uncertain)`
- 术语：首现配简短白话解释（严谨性与可读性兼顾）；前后同一术语拼写一致

## 四、实操完整性（要求 4）

- 每篇必须同时具备：**代码块 + 可执行命令 + 分步操作**；缺失即高严重度（纯概念文不合规）
- 代码：可运行、依赖与版本明确、有预期输出说明；发现错误 → 技术性修正并逐条报告
- 命令：可复制执行、标注运行环境（目录、权限、前置步骤）
- 步骤：编号分步，每步有可核对的结果（命令输出、文件生成、状态确认）
- 技术可信度并入本维：版本表述与官方口径一致、未验证内容列实机验证待办

## 五、实际应用（要求 5）

- 教程收尾有真实应用场景：生产配置、性能调优、故障排查、业务迁移等；只有玩具示例收尾 → 中严重度
- 应用节要具体：什么场景、什么参数、什么效果（量化或有来源）；给出读者迁移到自己业务的入手点
- 缺失时的补法：基于正文已有实操延伸一步（如把基准脚本用于真实负载参数调优）；延伸内容超出已验证范围时标 `(uncertain)` 并列实机待办

## 六、AI 痕迹与原创（生态红线，华为云明文）

按信号扫全文，命中记录位置与例句：

| 信号 | 表现 |
|------|------|
| 模板腔句式 | "本节将介绍""让我们""值得注意的是""总而言之"高密度出现 |
| 空洞收尾 | 每节结尾都是无信息总结段 |
| 无实据数字 | 性能数字 / 对比结论无来源、无测试环境、无复现命令 |
| 排比与堆叠 | 三段式排比、"不仅…而且…更…"递归堆叠 |
| 均匀结构 | 每节长度一致、小标题句式雷同 |
| 代码疑未跑 | 语法 / API 错误、输出与代码不匹配、版本含糊 |
| 未经证实断言 | 绝对化表述 + 无基线优劣结论 |
| 原创性问题 | 抄袭 / 未授权转载 / 翻译不标注、大段与单一来源重合 |

**痕迹密度分级**：低（1–2 类，AI 可改） / 中（3–5 类或代码疑未跑，AI 可改 + 关键段人工重写） / 高（6 类以上或整体 AI 生成，**必须**人工实机验证 + 亲口重写，AI 改稿不消除下线风险——此结论如实写进报告）。
