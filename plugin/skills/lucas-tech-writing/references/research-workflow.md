# research-workflow — 多源检索与逐篇消化

检索和消化是本 skill 的地基：**成文质量的上限由这一步决定**。目标不是"找到几篇文章"，而是
对主题形成一张知识地图——知道哪些块已被讲清、哪些块是缺口、哪些说法过时。

## 一、多角度检索

用 WebSearch，**3–5 个角度各查一轮**，中英文都查（英文一手资料通常更全、更新）：

| 角度 | query 范式（以主题 X 代入） |
|------|---------------------------|
| 是什么 | `X 是什么` / `what is X explained` / `X overview` |
| 怎么上手 | `X tutorial getting started` / `X 入门教程` / `X quickstart` |
| 原理机制 | `X how it works under the hood` / `X architecture internals` |
| 对比选型 | `X vs alternatives` / `X comparison 2025` |
| 踩坑 | `X common pitfalls` / `X troubleshooting FAQ` / `X 踩坑` |
| 进阶拓展 | `X best practices` / `X advanced tips` / `X performance tuning` / `X 生态 工具` |

- 用户给了范围限定（版本 / 语言 / 平台）时，**每个 query 都带上**限定词
- 快速迭代的技术（框架 / 模型 / 库）加年份限定，优先近 1–2 年的教程；稳定技术（协议 / 算法
  基础）不强制
- 每轮取前几条标题 + 摘要判断相关性，相关才进入精读

## 二、来源分级

同一块知识出现分歧时，按此优先级采信：

1. **官方文档 / 官方博客 / 官方仓库 README**（最高，事实与 API 的基准）
2. 官方发布说明 / changelog / 权威技术媒体的深度评测
3. 资深从业者博客（有具体细节、代码、可验证的经验）
4. 社区教程 / 问答（可用于补上手视角，事实须回官方源核对）

**弃用**：内容农场（洗稿、无细节、大量广告）、明显过时且无时效标注、与主题只是沾边的。
被弃用的文档**不计入核心参考**。

## 三、核心参考 ≥3 篇的判定

- **核心参考** = 真正被消化进成文的文档（至少贡献了一个知识块或一张图），不是只在文末挂名的
- 硬底线 **≥3 篇**；理想 3–6 篇，另有补充参考（只贡献个别事实）可再多
- **两轮多角度补搜后仍 <3 篇**：停下，如实向用户报告——找到了哪些、主题是否太窄 / 太新 /
  有歧义、是否换范围重搜，**与用户确认后再继续**。绝不硬凑不相关文档充数，绝不假装只有一篇
  也"够用了"

## 四、逐篇消化

对每篇入选文档用 WebFetch / fetch_content 读全文，提取六样东西（在会话内记录，**不落盘**）：

1. **它讲清了什么**：对应知识地图的哪些块，关键事实 / 数字 / 结论
2. **它缺什么**：只覆盖碎片的部分，明确记下来（后面靠别的文档或补查填）
3. **时效**：发布 / 更新时间、针对的版本；过时内容标注"不采"或"仅历史参考"
4. **代码**：有没有代码示例？能直接用还是要按最新版本调整？
5. **图片候选**：图 URL + 内容一句话 + 可能归位的知识块 + 水印初判（有 / 无 / 待查）
6. **口径**：术语译法、版本号、命名——多篇口径不一致时记下来，写作期统一

### 知识地图

一张覆盖表（会话内完成），行是知识块，列是来源，最后标缺口：

| 知识块 | 官方文档 | 博客 A | 教程 B | 缺口? |
|--------|---------|--------|--------|-------|
| 概念与背景 | ✓ | ✓ | 部分 | — |
| 原理机制 | 略 | ✓ | ✗ | 补查 |
| 安装与环境 | ✓ | ✗ | ✓ | — |
| 最小示例 | ✓ | ✓ | ✗ | — |
| 模块用法 | 索引级 | 部分 | ✓ | 补查 |
| 常见坑 | ✗ | ✓ | 部分 | 补查 |

固定知识块清单（按主题取舍，不是每个主题都有全部块）：

**概念与背景 / 原理机制 / 安装与环境 / 最小示例 / 各模块用法 / 对比与选型 / 常见坑与 FAQ /
进阶与拓展（调优 / 生态 / 边界 / 组合用法）**

标了"补查"的块进入下一阶段（见 `code-and-quickstart.md`）：查官方文档 / 仓库补齐。**缺口
跟着源文档走是拼凑感的根源**——一篇缺原理、一篇缺实操，直接串写必然断档；填平缺口才能成
一篇完整的文章。
