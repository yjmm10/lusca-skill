# image-workflow — 图片抓取、水印分级与署名

博客必须配图。图片来源以**源文档的图为主**（架构图 / 流程图 / 效果图 / 界面截图），封面用
兄弟 skill 的 fetch_cover.py（库存图池，无水印问题）。图片处理三道关：**下载 → 逐张目检 →
水印分级**。

## 一、候选图清单

消化阶段（见 `research-workflow.md`）顺手记录，每张候选图标明：

- 图 URL 与所在源文档
- 内容一句话（"整体架构图""某个模块的时序图""基准对比柱状图"）
- 可能归位的知识块
- 水印初判（有 / 无 / 待查）

## 二、选择原则

- **按叙事需要嵌**：这张图放在这里能少写三行字 / 让新手一眼看懂，才嵌；不是每个来源摊一张，
  更不是凑数
- 数量：正文 2–6 张为宜 + 封面 1 张；全篇零图通常说明选图不力（架构 / 流程类主题总该有图）
- 源文档没合适的图、叙事又确实需要（如流程）→ 用 mermaid 自绘替代，**不要**为此去嵌带水印的图

## 三、下载（必跑脚本）

把候选清单写成 manifest JSON：

```json
[
  {"url": "https://example.com/arch.png", "name": "01-arch", "source": "https://example.com/docs/architecture", "note": "整体架构图"}
]
```

跑：

```bash
python3 "$IMGFETCH" --manifest imgs-manifest.json --output-dir outputs/lucas-tech-writing/<slug>/imgs
```

（`$IMGFETCH` = 本 skill 的 `scripts/fetch_images.py`，见 SKILL.md 路径约定。）

脚本自动做：格式嗅探（png/jpg/gif/webp/bmp/svg）、大小校验、内容 hash 去重、文件名防撞。
读 `===RESULT===` 拿每张的落盘路径；失败的张目如实上报，不静默跳过。

## 四、逐张目检

`Read` 每张下载好的图，确认三件事：

1. **内容匹配**：图的内容与要归位的知识块一致（下载错图、图文不符的弃用）
2. **清晰可读**：缩略图、模糊图、字小到看不清的弃用
3. **水印检查**：仔细看四角、底部、中央半透明区域

> SVG 无法用 Read 目检——无法查水印，默认弃用；确要用（如官方文档的 svg 示意图且确认无
> 水印层）须在交付要点里说明。

## 五、水印分级（核心规则）

| 情形 | 处理 |
|------|------|
| 无明显水印 | 直接用，图注署名来源（见 §六） |
| 有水印，且能找到无水印替代 | **弃用换图**：同主题他源无水印图，或 mermaid 自绘 |
| 有水印，但该图稀缺且确有必要 | 保留原样使用 + 图注**显著**标注来源与水印说明 |
| 图库大水印（shutterstock / 视觉中国类） | 一律不用——版权风险，替代也找不到就宁可无图 |
| 公众号底部二维码 / 推广条截图 | 裁掉推广条不可取（等同改图），整张不用或换图 |

**红线：绝不裁剪、涂抹、遮挡水印。** 水印是来源与权利信息，去掉 = 篡改出处；需要图就正大
光明带水印 + 署名，或者不用。

水印高发区提醒：公众号文章图（右下角"微信扫一扫"角标 / 公众号名水印）、CSDN / 掘金截图
（角落用户名水印）、AI 生图（角落生成器水印）。

## 六、署名格式

每张嵌入的图必须有 alt + caption（**严禁只写文字路径**）：

```markdown
![XX 整体架构](imgs/01-arch.png)

> 图：XX 的整体架构，数据自上而下流经三个模块（图源：[官方文档 · Architecture](URL)）
```

- 带水印保留的图，caption 额外加一句：`（原图含来源站点水印，特此标注出处）`
- mermaid 自绘的图 caption 写 `（作者自绘）`，不冒充来源图
- 封面图（fetch_cover.py 的库存图）无 caption，frontmatter 记 `cover_source`
