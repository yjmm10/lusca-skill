# 多平台采集策略 — lusca-news-report

本文件给「多平台采集」阶段的操作细节：每类渠道怎么构造检索词、典型入口、采集什么、注意事项，末尾附信源可信度分级表。`SKILL.md` 讲 why（为什么要全平台），本文件讲 how（每个平台具体怎么搜）。

## 检索词构造通则

- **中英双查**：国内事件以中文词为主、英文词补；国际事件反之
- **加主体限定**：`<事件关键词> <主体名>`、`<产品名> <事件>`，避免同名噪声
- **加时间限定**：`<事件> 2026年` 或 WebSearch 的 time range，排除旧闻
- **平台定向检索**：用 `site:` 限定渠道——`site:zhihu.com`、`site:reddit.com`、`site:weibo.com`、`site:x.com`、`site:bilibili.com`、`site:xiaohongshu.com`——快速进对应社区
- **官方定向**：`<主体> 官方 公告/声明/致歉/回应`、`<主体> 微博`、`<主体> site:<官网域名>`

## 五类渠道

### 1. 官方（宣传方式 + 答复）

采集官方"怎么说"：宣传口径、营销话术、声明、致歉、对质疑的答复。

- **入口**：官网公告 / 新闻页、官方微博、官方公众号、X/Twitter 官方账号、发布会 / 直播实录、官方 FAQ / 致歉信
- **检索词**：`<主体> 官方 公告/声明/回应/致歉`、`<主体> 微博 官方账号`、`<主体> site:<官网域名>`
- **要记什么**：
  - 宣传方式：怎么包装的、主打什么卖点 / 话术、投放渠道
  - 官方答复：对争议 / 质疑 / 事件的正式回应、致歉、整改承诺
  - 口径变化：不同时间点说法是否一致（用于时间线）
- **注意**：官方说辞是"宣传口径"，**不等于事实**——与一手 / 权威冲突时并列记、标可信度；官方答复要溯源到可点击链接

### 2. 权威媒体（事实层核实）

采集"实际发生了什么"的核实性报道。

- **入口**：主流权威媒体（视事件地域 / 领域而定）、通讯社稿、调查报道
- **检索词**：`<事件> 报道/独家/调查`，限定权威媒体名
- **要记什么**：关键时间点、关键数字、当事人 / 方表述、被证实的事实
- **注意**：权威媒体之间互相引述时，追到**首发 / 一手报道**；区分"媒体已核实"与"媒体引述他人说法"

### 3. 社交平台 / 社区（舆论倾向 + 用户评价）

采集大众怎么看：舆论倾向、争议焦点、代表性观点。

- **入口与 site: 限定**：
  - 微博：`<事件> site:weibo.com`、微博热搜词条
  - 知乎：`<事件> site:zhihu.com`、相关问题与高赞回答
  - Reddit：`<事件> site:reddit.com`
  - X/Twitter：`<事件> site:x.com`
  - B站：`<事件> site:bilibili.com`（视频评论 / UP 主解读）
  - 小红书：`<事件> site:xiaohongshu.com`
  - 抖音：`<事件> 抖音`
  - V2EX / Hacker News / Product Hunt：技术 / 产品事件定向
- **要记什么**：
  - 舆论倾向：正 / 中 / 负的大致分布（不要只挑最赞或最骂）
  - 争议焦点：大家在吵什么、哪些点反复被提
  - 代表性观点：每方挑 1-2 条高赞 / 有代表性的引述（注明出处）
- **注意**：社交平台情绪化、易带节奏——作"舆论切面"记，不作事实层；水军 / 刷榜嫌疑要标注

### 4. 用户评价（真实使用者反馈）

采集真正用过 / 买过 / 经历过的人的反馈。

- **入口**：
  - 应用商店：App Store / Google Play 评论与评分（产品 / APP 类事件）
  - 投诉平台：黑猫投诉、12315（消费 / 服务类事件）
  - 电商评价：淘宝 / 京东 / 亚马逊评价与差评（商品类事件）
  - 评测社区：豆瓣（影视 / 书）、大众点评（餐饮 / 服务）等垂直评价
- **检索词**：`<产品/服务> 应用商店 评价/差评`、`<主体> 黑猫投诉`、`<产品> 电商 评价`
- **要记什么**：评分分布、典型好评 / 差评点、投诉集中问题
- **注意**：评价有刷单 / 水军可能，看分布而非单条；标注样本量与采集时间

### 5. 垂直专业（行业视角）

采集业内人士 / 分析师 / 专业评测怎么看。

- **入口**：行业垂直媒体、专业评测机构、领域 KOL / 博主、分析师报告
- **检索词**：`<事件> <行业> 分析/解读/评测`、领域 KOL 名 + 事件
- **要记什么**：行业怎么看、专业层面的判断、与同类事件 / 产品对比
- **注意**：KOL 有利益相关（恰饭 / 代言）可能，标注；专业判断比大众情绪更可信但仍是一家之言

## 图片采集（各渠道通用）

每类渠道采集文字时，**同步留意可下载的关键图片**——纯文字报告读起来干，且官方截图/数据图本身就是证据：

| 渠道 | 重点图片类型 |
|------|-------------|
| 官方 | 公告截图、声明全文图、发布会 PPT、致歉信 |
| 权威媒体 | 事件现场照、信息图、数据图表 |
| 社交平台 | 高赞帖子截图（**模糊头像/ID 保护隐私**）、热搜截图 |
| 用户评价 | 评分分布截图、典型评价截图（模糊用户信息） |
| 垂直专业 | 行业分析图表、产品对比图、评测截图 |

**获取方法**：

- WebFetch 返回内容中注意出现的图片 URL，挑相关的 `curl -L -o imgs/<descriptive-name>.<ext> "<img-url>"` 下载
- 若需提取页面全部图片地址：`curl -sL "<页面URL>" | grep -oiP '<img[^>]+src="\K[^"]+"'` 扫出后人工筛
- **只下载页面中真实存在的图片 URL，绝不编造图片地址**
- 社交平台截图注意隐私：模糊个人头像和用户 ID 后再嵌入，或只引述文字不嵌图

**嵌入规则**：每张图配**事实性 caption**（"图：X 官方公告截图，来源：[链接] / [序号]"），与文字来源索引交叉引用；某节无图可采不硬凑，留文字即可。

## 按事件类型裁剪平台

不必每个事件都扫全平台，按事件性质聚焦（在报告里说明扫了哪些、没扫哪些）：

- **技术 / AI 产品事件**：HN / Reddit / V2EX / 知乎 / X / 技术媒体 / 应用商店
- **消费 / 产品事件**：小红书 / 电商评价 / 应用商店 / 黑猫投诉 / 微博 / 知乎
- **政策 / 社会事件**：权威媒体 / 官方 / 微博 / 知乎
- **企业 / 商业事件**：权威财经媒体 / 官方公告 / 投资者社区 / 知乎

## 信源可信度分级表

报告"信息来源索引"按此分级标注每条来源，让读者自行权衡：

| 等级 | 类型 | 示例 | 可信度 |
|------|------|------|--------|
| 一手 | 官方 / 当事人 / 权威通报 | 官网公告、当事人声明、权威机构通报 | 高（但官方口径可能有宣传成分） |
| 权威 | 主流权威媒体核实报道 | 通讯社、主流大报调查报道 | 高（追到首发 / 核实稿） |
| 垂直 | 行业垂直媒体 / 专业评测 | 行业媒体、专业评测机构 | 中高（注意利益相关） |
| 社区 | 社交大V / KOL | 领域 KOL、高赞博主 | 中（注意恰饭 / 立场） |
| 大众 | 普通用户评论 / 帖子 | 应用商店评论、社交帖子 | 中低（作舆论切面，非事实） |
| 存疑 | 营销号 / 匿名消息 / 未证实 | 自媒体互抄、匿名爆料 | 低（单独标注，不莫名深挖） |

> 同一事实若多个等级来源一致，可信度上升；若冲突，在报告里如实并列、标各自可信度，让读者判断。
