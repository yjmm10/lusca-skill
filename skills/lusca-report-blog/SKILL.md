# lusca-report-blog — 报告博客化解读

**核心理念：博文的一切为了给读者提供知识价值——把报告里有价值、读者真正关心的信息呈现出来、讲清楚，让读者读完觉得"省了时间、抓住了重点、搞清楚了这事"。作者的价值不靠观点论证体现，而靠筛选（挑出高价值、读者在意的）+ 组织（连成一张清楚的图）+ 讲明白（为什么重要、对你意味什么）。所以博文是整理加工、是说清楚，不是论证——读者感受到的是作者帮他抓住了价值，不是作者在发表观点。博文自包含，发布出去也不依赖本地报告文件。**

输入一份报告（`lusca-news-report` 的事件报告、调研报告、研究报告、行业分析等），用**领域关切**与**行业共鸣**拉近距离，用**自问自答和轻度打趣**让语气亲和（生活类比只用于解释具体概念），产出通俗、可发布、段落短小但不丢要点的博文。立足**读者价值视角**：目标是让读者愿意点开、读完、带走知识价值并搞清楚事情，而非复述报告或做学术评估。

## 主流程

```
locate → read → select → outline → write → polish → save
```

1. **定位报告**：解析 `$ARGUMENTS`，`Read` 报告全文
2. **读透 + 筛选**：提炼六样——主题/背景、核心事实、关键数据/图表、各方立场或反应、报告自己的分析/结论、caveat/不确定；**据此筛选高价值、读者真正关心的内容**——报告可能很长、模块很多，博文只呈现读者需要知道、真正在意的部分，不必把所有模块搬进来。建立图片清单，图**复制**到博文自己的 `{slug}/imgs/`
3. **搭骨架**：`Read` `assets/report-blog-template.md`，对照模板规划各节。**以"说清楚 + 交付价值"为纲**：围绕**读者想知道/该知道的**组织（不是围绕报告结构）；节怎么分服从于把事情讲明白（综合叙述或按视角组织皆可）；**不设**"我怎么看""时间线"这类节（见 §总纲）；澄清 inline 在关键处；时间线折进正文一句或省。选活泼标题（报告关键词 + 钩子）
4. **写博客**：按节逐段写，遵循「核心准则」——价值导向、通俗、深入浅出、行业共鸣、互动语气、**澄清式作者在场**、篇幅、段落控制
5. **润色语气**：通读——删官样腔与凑数段（每段都该有知识增量）、补自问自答与打趣（点缀别过密）、拆长段、确认每段 ≤4-5 行、确认没有"我怎么看/时间线"节、确认没有本地报告路径、确认末尾是"参考来源"
6. **落盘**：写到 `./outputs/lusca-report-blog/{slug}/{YYYYMMDDHHmmss}_{slug}.md`，图**复制**到 `{slug}/imgs/`；带 frontmatter；**文末出处块**三行
7. **交付**：路径 + 标题 + 一句话定位；附后续衔接；**不内联重复展示完整博客**

## 核心准则（风格同源 lusca-paper-blog，报告场景适配）

### 价值导向：呈现高价值、读者关心的内容（博客存在的理由）

博文的一切为了**给读者提供知识价值**。这条是目的，下面所有准则是手段：

- **挑高价值、读者真正关心的内容呈现**：报告可能很长、模块很多——博文不是机械转录，而是**筛选**出读者需要知道、真正在意的部分（核心事实、关键转折、各方表态里的信号、对读者意味什么）。读报告时心里始终问："读者会想知道这个吗？这个对他有用吗？"——没用的、重复的、凑数的，砍
- **每段都要有知识增量**：事实 / 背景 / 意义 / 对你意味什么——至少占一样；写完一段问"读者从这段拿到了什么"，拿不到就删或改
- **围绕读者想知道/该知道的来组织**，不围绕报告的原结构；读者打开博文是带着问题的（"这模型到底强不强""这事跟我啥关系"），博文按这些问题给答案
- **作者的价值 = 筛选 + 组织 + 讲清楚**：筛出了什么（curation）、连得清不清楚（synthesis）、点没点出"为什么重要 / 对你意味什么"（significance）——读者读完觉得"省了时间、抓住了重点、搞清楚了"，就感受到了作者的价值。**不是靠"我有独到观点"**（那反而违背下条总纲）

### 总纲：整理加工、把事情说清楚，不是论证

价值靠"整理加工、说清楚"来交付，而**整理加工的底线是——不是论证**。本技能产出的是**对信息的整理加工**，不是论证文：不论证某个论点、不打分评价、不替读者下结论。

- **作者穿插的是"澄清"，不是"观点"**：消化信息后给出"这意味着什么""这点各来源一致 / 冲突""这数字最值得在意的是…""这里还没证实"——这是把价值说清楚；但**不写成"我认为…""我建议大家…"**。允许解释性澄清（"更合理的理解是…，因为…"），不允许立场性论证
- **结构服从"说清楚"**：怎么分节，取决于哪种讲得更明白——综合叙述、按官方/媒体/社区视角、按内容主题，皆可，看哪个帮读者看清
- **三件事不属于"说清楚"，禁用**：① **"我怎么看 / 我的看法"节**——评论专栏，非整理加工；② **"时间线"节**——报告机械构件，重要就折进正文、不单设；③ **"关键来源"标签**——论证证据清单；末尾给的是**"参考来源"**（供查证）
- **不替读者下结论**：把"什么站得住、什么有争议、什么没证实、对不同人意味什么"说清楚即可；读者自会判断

### 通俗：把报告"翻译"成人话（保留专业名词让人学到）

- **保留专业名词 + 配白话**：术语首次出现用「术语（白话解释）」，如"MoE（混合专家架构，总参数大但每次只激活一小部分上场）"
- **指标给判读方向**：报数字附带"是什么量、越高/越低越好"
- **绝不编造**：报告没说的不补；报告标了 `(uncertain)` 的沿用；事实忠于原报告

### 深入浅出：背景 → 核心 → 影响

先讲**报告为什么值得读**，再讲**核心内容**，最后讲**影响/与你何干**；复杂处配一个生活类比；循序渐进。

### 行业共鸣：戳读者的领域关切

导语用报告主题相关的领域痛点或近期事件切入；生活类比只用于解释概念、不作共鸣主线；痛点具体到方向/场景/角色。

### 语气：自问自答 + 轻度打趣

用"为什么会这样？因为……"推进；过渡处轻度打趣拉近距离；边界：严肃处（数字、未证实点、澄清）克制不打趣。

### 澄清式作者在场：穿插澄清，不设观点节

作者的价值是**消化后的澄清**（见价值导向），不是观点论证：

- 在关键处给澄清性解读："这数字最值得在意的是…""各来源在这点上是一致 / 冲突的""更合理的理解是…，因为…"
- 标出站得住 / 有争议 / 未证实：哪些被多方证实、哪些仅见于一处、哪些官方自报
- **不单设"我怎么看 / 我的看法"节**；澄清散落在讲到对应内容的关键处 inline
- 边界：基于报告事实；报告没有的不补；解释性澄清允许、立场性论证禁止

### 篇幅与节奏

目标 **2000–4500 字**；每段 ≤4-5 行；多用小标题与列表但保持叙事连贯。

### 结构：TL;DR 开头、服从说清楚、段间承接

- **一句话总结放开头作 TL;DR**（说清楚后的图景：什么站得住/有争议/对读者意味什么），结尾不重复
- **节怎么分服从"说清楚"**：综合叙述、按视角（官方/媒体/社区）、按内容主题——选讲得最明白的，可混搭；视角组织的节里讲清"各方怎么说、有无旁证、一致还是冲突"，不写"对/错"评价
- **三不设**（硬规矩）：不设"我怎么看/我的看法"节、不设"时间线"节（折进一句或省）、不设"冷静一下/注意事项"割裂附录标签
- 收束若有，用**承接上文 / 回调导语钩子的过渡**起头（"把话说明白""在你 X 之前""不过话说回来"），作为"说清楚"的自然收尾
- 并列分点（≥3）用 markdown 列表；段间有承接

### 标题：活泼 + 报告关键词 + 钩子

用易识别关键词（事件名/产品名/主题），不塞冗长全标题；加单个钩子；小标题（H2）干净直白（直白问句或主题短语），**不带"我怎么看""时间线"这类**、不带指导性括注。

### 图片与视觉：氛围图一张 + 报告原图复制进 imgs 该嵌就嵌

- **氛围图一张（开头）**：Bing 每日一图（取不到降级 picsum.photos），H1 后正文最开头，无 caption；**正文直接用外链 URL 嵌入**（同时下载一份到 `imgs/cover.<ext>` 备份），frontmatter `cover` 记**外链 URL**、`cover_backup` 记本地备份、`cover_source` 记来源描述（`Bing 每日一图 · <copyright>` 或 `picsum · seed=<slug>`）
- **报告原图复制进博文 imgs、该嵌就嵌**：报告里的数据图/关键截图是事实层，**复制到博文自己的 `imgs/`**（用 `imgs/xxx.png`），嵌入正文配白话 caption。严禁只写文字路径、严禁引用报告目录原路径（见 §输出解耦）
- **emoji 适当点缀**：H2 配语义 emoji、列表关键词配相关 emoji；数字/caveat 严肃处不加

### 资源块：参考来源（外链）前面给

- 导语后、正文前，放资源块：报告涉及的**外部公开来源**（官网/媒体报道/社区帖子/公开 demo），引用块、每条一行、markdown 链接
- **只放外链，不放本地报告路径**（见 §输出解耦）；报告本身有公开 URL 才给
- 用博文语气领起（"想自己动手？""参考来源在这"）

## 报告特有准则（与论文博客的领域差异）

### 输出解耦：博文自包含，不依赖本地报告文件（硬约束）

博文是要发布出去的独立产物，必须**自包含、与源报告解耦**——读者只看这篇博文（+ 它自己 `imgs/` 的图）就能完整理解：

- **不嵌入完整报告内容**：读透后用自己的话重讲，不复述大段报告原文
- **资源块只放外链，不放本地报告路径**：外部公开来源可给；**不给本地报告文件的相对路径链接**（发布后断链）。报告 hosted 在公开 URL 才给
- **本地文件只用 imgs/**：报告里的图**复制进博文自己的 `imgs/`**；除此之外不引用任何本地文件内容
- **frontmatter `source_report` 只写报告标题**（出处标注，不带本地文件名/路径），同 slug 即可回溯

> 为何解耦：博文一旦脱离本工作区（发公众号 / 博客平台），本地路径全断链、"见报告第 X 节"全落空。自包含才能独立传播。

### 说清楚 + 交付价值，不是论证（领域落地）

总纲与价值导向在报告场景的具体化——报告天然带"评估/分析"模块，很容易把博文写成"评论/评价"。守住整理加工、交付价值的定位：

- **按视角组织内容是允许的**：报告的"各方反应"模块，可按官方/媒体/社区组织，帮读者看清"各方怎么说"——这本身是整理加工、是交付价值，不违反总纲
- **但组织方式服务"说清楚 + 价值"，不是服务评价**：视角小节里讲清"这一方说了什么、有没有被旁证、和别方一致还是冲突、对读者意味什么"，不要变成"这一方对/错"的评价
- **综合进作者的话仍是首选**：当视角分节会让信息碎片化时，用作者口吻把多方融成连贯叙述更清楚；某方有若干天然并列的具体观点，用分点列表逐条列（列表项作者口吻、不带来源标签前缀）。一句话：**按来源分"节"看是否服务说清楚，按内容点列"表"可以**
- **作者澄清 inline，不设"我怎么看"节**（遵总纲）；事实与澄清融进同一段叙述，不拆"事实节 + 评估节"

### 时间线：折进正文，不单设节

报告有时间发展、且**对说清楚是必要的**，才在正文叙述里用一句话或一小段带出关键节点；**不要单设"时间线"节**。多转折的长事件非得可视化时，用 mermaid 或精简列表**嵌在相关叙述处**，也不单设"时间线"节。

### 收束：澄清式收尾，不用割裂标签

末尾若收束，是"把事情说清楚"的自然落点——综合出"什么站得住、什么有争议、什么没证实、对不同人意味什么"，用承接上文/回调钩子的过渡起头（"把话说明白""在你 X 之前""不过话说回来"）。**不用"冷静一下/注意事项"这类割裂附录标签**，也**不用"我怎么看"**。caveat 优先折进正文相关处。

### 参考来源：供查证，不是论证证据

- 末尾附**"参考来源"**（不是"关键来源"）：从报告的来源索引挑 3–8 条最关键的、**带公开外链**的，标注类型/可信度，**供读者查证出处**——呼应整理加工定位，而非论证证据
- 只给有公开 URL 的来源，不列纯本地引用；报告标了"官方自报/showcase"的，博文传递这层保留

### 数据/图表

报告的关键数据图/表**复制进 imgs** 嵌入 + 白话 caption；把支撑结论的关键数字摆出来（报告里已有的表可精简转写）。

## 输出与存放

- **目录结构**（图**复制**到博文自己的 `imgs/`）：
  ```
  outputs/lusca-report-blog/{slug}/
    ├── {YYYYMMDDHHmmss}_{slug}.md   # 博文（自包含，不依赖本地报告）
    └── imgs/                         # 氛围图 + 从报告复制来的图
  ```
- **slug**：取自报告主题或事件名（kebab-case）；可与上游同 slug 以便对照
- **frontmatter**：`title`（活泼版）/ `subtitle`（可选）/ `source_report`（原报告**标题**，不带本地路径）/ `blog_date` / `read_minutes` / `slug` / `tags` / `abstract`（≤200 字博文摘要）/ `cover`（氛围图外链 URL）/ `cover_backup`（本地备份路径）/ `cover_source`（可选，来源描述）
- **`abstract` 是 frontmatter 的博文摘要**（≤200 字中文）：用于平台描述/SEO/列表预览，概括"报告讲了什么、说清楚后的图景、对读者意味什么"；与正文 TL;DR（一句话钩子）互补——abstract 是完整段落、TL;DR 是一句话
- **`cover` 必须是 http(s):// 开头的图片直链**——正文实际能加载的远程图片地址，❌ 严禁填 `Bing 每日一图 · <copyright>` 或 `picsum · seed: …` 这类文字描述（文字来源描述放 `cover_source`）；落盘前自检 `cover` 以 `http` 开头
- **文末出处块**（遵 CLAUDE.md，三行）：
  ```
  > 作者：lusca
  > 版本：lusca-report-blog v<version>
  > 出处：https://github.com/yjmm10/lusca-skill/tree/main/skills/lusca-report-blog
  ```
- **段落不硬换行**：正文段落与列表项写在一行，段间空行分隔
- **交付精简**：落盘后只返回路径 + 标题 + 一句话定位，**不内联重复展示完整博客**
