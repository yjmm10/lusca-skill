# 技术选型参考

使用方式：先问清约束（团队熟悉的技术、生态诉求、部署目标、性能要求），再从表里筛出 2-3 个合适方案，**以选项形式给用户**，每个附一句理由与代价。不替用户拍板。

## 前端

| 方案 | 适合 | 代价 / 注意 |
|------|------|-------------|
| Vue 3 + Vite | 中后台、交互密集型应用、国内生态友好 | 需遵守 tokens 统一约定，避免样式散落 |
| React + Vite | 组件生态最大、团队已有 React 经验 | JSX 心智负担、依赖选型自由度高需自律 |
| Next.js | 需要 SSR / SEO 的站点 | 部署到 GitHub Pages 只能静态导出，动态能力受限 |
| Astro | 内容型站点、博客、文档站 | 交互组件按岛屿模式按需引入 |
| Svelte / SvelteKit | 追求体积小、语法简洁 | 生态相对小、招人面窄 |
| 原生 + Vite（无框架） | 简单展示页、性能敏感小工具 | 状态与路由需手写，复杂度上来后难维护 |

## 后端

| 方案 | 适合 | 注意 |
|------|------|------|
| FastAPI（Python） | API 服务、AI 应用、快速迭代 | 异步与依赖注入有学习曲线；配 pydantic-settings 管配置 |
| Express / Fastify（Node） | 轻量 API、与前端同语言 | 架构约定靠团队自律，建议分层（api/services） |
| NestJS（Node） | 大型 Node 服务、需要强结构 | 模块化/装饰器较重，小项目过度设计 |
| Spring Boot（Java） | 企业级、复杂领域模型 | 启动慢、内存开销大，小项目不划算 |
| Gin（Go） | 高并发、单二进制部署简单 | 生态库需要自己拼装 |
| Django（Python） | 全功能、自带 admin 与 ORM | 默认单体，高度定制需要经验 |

## 决策提醒（主动反馈用）

- 只做一个展示页 → 不必上前端框架，原生 + Vite 足够
- SEO 是硬需求（官网/文档）→ 静态生成优先，SPA 是下策
- 团队只有一种语言的经验 → 优先该语言的主流方案，不追新
- 需要用户登录 / 数据库 / 定时任务 → 必须有后端，GitHub Pages 只能托管前端静态部分
- 前后端都要且团队小 → 优先同语言栈（如 Next.js 全栈 或 Vue + Express），降低维护面
