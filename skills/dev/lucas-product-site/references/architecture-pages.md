# 页面架构与动效

三页分工：落地页负责理解与转化，数据页负责事实与核验，关于页负责主体介绍与边界说明。信息只在一处展开，跨页用链接衔接，不重复整段文案。

## 落地页

推荐顺序：

1. Hero：一句主张 + 一句解释 + 一个明确 CTA + 来自数据的信息徽章（指标数、最近更新、可核验声明）；背景可用克制的新变与网格纹理，不抢正文。
2. 产品预览：用浏览器窗口样式的容器（红黄绿点 + 地址栏）包住 `gallery` 渲染图/真实截图，让占位插画也显得像产品界面；可切换 2-4 张，默认不自动轮播。
3. 核心指标：从 `highlights.metrics` 取 3-6 个，按重要性排；每张卡显示来源与时间。
4. 最新动态：从 `highlights.latest` 取前 3 条，显示日期、标题、摘要和链接。
5. 能力/场景：从 `highlights.features` 取 3-6 个，按用户决策路径排列。
6. FAQ：只展示数据中存在的问题与答案。
7. CTA：回到数据页或联系入口。

动效：进场渐显、数字轻动、预览切换、主题切换过渡即可；尊重 `prefers-reduced-motion`。不要让动画成为理解内容的必要条件。

## 数据页

- 顶部写清“数据更新时间 / 统计口径 / 来源说明”。
- 指标表格支持排序、搜索、按标签筛选；无 JS 时也应能读到完整表格。
- 移动端把宽表转卡片，优先显示指标名、数值、周期。
- 空状态写“为什么为空”和“怎么恢复”，错误状态写可联系入口或来源链接。
- 数据来源与方法论链接到原始出处，不把本站自己当来源。

## 关于页

- 产品：为什么存在、解决什么问题、适合谁、不适合谁。
- 作者/团队：真实名称、角色、简介、可核验链接。
- 免责声明：数据时效、非建议声明、商标/版权归属、第三方链接责任边界；写得具体，不用模板腔。
- 结尾不放“AI 生成/仅供参考/欢迎指正”式尾巴。

## 职责边界（理论，不限定实现）

以下职责划分是理论指引，实际文件名/组件拆分由 AI 按产品差异化决定，验收只看职责是否完整、数据是否单向流动：

- **布局层**：head 元信息、结构化数据、主题初始化、页头页脚、语言切换——全站唯一，不掺业务逻辑
- **派生层**：落地页最新区块只读派生数据（`highlights.json`），绝不手写第二份事实
- **数据展示层**：完整数据呈现与筛选排序，与派生摘要分离
- **主题层**：主题状态与切换独立，不处理业务数据

单一职责让后续替换组件库时不牵动数据逻辑。

## 差异化要求（反模板）

- **验收标准统一，实现千站千面**：本页给的是信息架构与职责理论，不是布局模板——同类型产品的两个站不应长得一样；布局骨架、视觉语言、组件拆分、命名都从产品特质出发
- **先答「这个产品的用户决策路径是什么」，再定页面结构**：工具型产品重预览与能力，数据型产品重指标与溯源，服务型产品重信任与联系——推荐顺序可按决策路径重排，但信息只在一处展开、跨页链接衔接的原则不变
- **视觉语言服务产品气质**：数据密集型克制冷静，创意型可大胆；动效、留白、色彩强度都从产品定位推，不从「上次怎么写」抄
