# UI 组件调研

目标：选到与产品数据匹配、维护可靠、能融入深浅主题和中英文的组件，而不是堆一个流行库。

## 检索步骤

1. 先看数据形态：指标卡、表格、筛选、图表、画廊、FAQ、代码预览分别需要什么组件。
2. 搜索 3-5 个候选，优先官方文档、GitHub README/CHANGELOG、可访问性说明；技术博客只作补充。
3. 核对最近提交/发布、issue 响应、版本稳定性、许可证、SSR/静态输出兼容、是否支持键盘与读屏。
4. 测包体影响：能否按需导入、能否服务端渲染、是否需要整体 hydration。
5. 把结论写进 `docs/ui-decisions.md`，附来源链接和访问日期。

## 决策矩阵

| 维度 | 要问的问题 |
|------|-----------|
| 维护 | 最近发布多久？issue 是否有人回应？版本是否稳定？ |
| 无障碍 | 键盘、焦点、ARIA、读屏是否有文档或测试？ |
| 包体 | 是否 tree-shake？是否会强制 React 全站 hydration？ |
| 主题 | 是否支持 CSS 变量/属性选择器切换深浅主题？ |
| i18n | 文案是否可覆写？日期数字格式是否可本地化？ |
| 许可 | 许可证是否允许项目用途？是否需要署名？ |
| 集成 | 与 Astro 静态输出、Tailwind token 是否冲突？ |

## 默认策略

- 结构简单的 Hero、卡片、表格、FAQ：用原生 Astro + Tailwind，避免引入运行时。
- 图表/复杂表格/轮播：优先选可 SSR 或只在可视区域加载的轻量组件；引入 React 岛屿时用 `client:visible` 或 `client:idle`。
- 不要为了“看起来现代”引入整站组件库；样式统一靠 token，组件统一靠少量可复用 Astro 组件。
