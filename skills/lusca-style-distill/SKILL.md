# lusca-style-distill — 写作风格提取

**核心理念：提取风格是把"这段文字听起来像谁在说话"变成一份可被复用的工程化画像——每条判断都能指回原文，不是文学赏析。**

给一篇文章（或同一作者的若干篇），按六个维度把它的写作风格抽出来，产出一份带原文佐证的"风格 DNA"：
语态人格、句法、用词、修辞意象、节奏结构、论证姿态各是什么样、有哪些签名习惯、想写成这种风格该照做
什么 / 别做什么。产出面向**复用**——agent 或人拿着这份画像能判断"像不像、怎么靠拢"，而不是写一段感性
鉴赏。

本技能只抽**"怎么说"（风格）**，不评价**"说什么"（内容）**对不对。两者正交：同一篇可先抽风格、再精读内容。

## 主流程

```
locate → read-sample → genre-decide → profile → evidence-check → save
```

1. **定位来源**：`Read` 读入文章（多篇则全部读入）
2. **取样阅读**：超长篇不必逐字读全——取样代表性段落（开头 / 中段 / 结尾 + 风格明显变化处），让取样覆盖
   全文而非只看开头；短文通读
3. **文体判定**：判定通用 vs 学术/技术（见下文「文体判定」），决定用哪套模板
4. **抽画像**：`Read` `references/style-dimensions.md`，按 6 维度逐维提取，**每条判断紧跟一句原文佐证**；
   多篇时再 `Read` `references/multi-article-merge.md` 做合并与置信度标注
5. **佐证自检**：逐条核对"有没有原文佐证、有没有脑补、文体侧重对不对、可迁移清单是不是具体动作"
6. **落盘**：按对应模板（`assets/general-template.md` 或 `assets/academic-template.md`）写到输出目录，
   带前置 frontmatter 与文末出处块

## 核心准则

### 每条判断必带原文佐证（不脑补）

任何"句式短促""爱用比喻""语气克制"都必须紧跟一句原文引用作为证据。**没有原文支撑的风格判断不要写。**
这条是本技能的最高准则——风格提取最坑的失败模式就是甩出一堆无从核对的形容词（"语言生动""富有张力"），
读完画像仍不知道这人到底怎么写。好画像的每一条，读者都能立刻在原文里指出来。

写法上，每条判断用"特征 + 佐证"两段：先一句话点出特征，再引一句原文。例：

> **句式以短促断句为主**：连续短句用句号切断，重音压在句末。
> 佐证：「他没说话。把杯子放下。转身走了。」（开头三句，各 5–7 字）

### 区分一次性文风 vs 稳定 DNA（多篇时）

多篇合并时，反复出现的特征才是作者的稳定 DNA；只在一篇里出现的更像那次的一次性文风。**前者标"贯穿
N 篇 / 高置信"，后者标"仅见于《某篇》/ 低置信"**，不混为一谈。详见 `references/multi-article-merge.md`。

### 画像要可迁移、可执行

Do / Don't 写**具体动作**，不写没法照做的空话。

- ❌ "语言生动""富有节奏感""充满力量"
- ✅ "每段收一句短促判断（≤10 字）作结""用'换句话说''也就是说'做段间承接""类比只取材于做菜与体育"

判断标准：拿到这条 Do/Don't，一个人能不能照着做。不能——就改成能的。

### 给反例

写出什么样**不属于**这个风格，防止画像被滥用、被套到不合适的场景。反例同样要具体（"这段为什么不像他
——因为……"），最好附一句"如果看到 X，那就跑偏了"。

### 风格 ≠ 内容

只抽"怎么说"，不评价"说什么"对不对、论证成不成立。内容质量交给 `lusca-paper-read`，本技能不越界。

## 文体判定：通用 vs 学术/技术

**学术/技术信号**（命中即倾向学术/技术）：IMRaD 或 Abstract / References / 公式 / "et al." / 实验与结果
章节 / 被动语态密集 / 术语稳定性要求高 / claim 配 hedging（"suggest / may / consistent with"）。

**通用信号**：专栏 / 科普 / 散文 / 评论 / 叙事，无上述结构，人格与修辞更外显。

**两套模板侧重不同**——6 维度是统一的，但学术/技术更看重**时态与语态、术语与引用纪律、claim 校准、
公式与数据如何嵌入散文、段落主题句习惯**；通用更看重**语态人格、修辞意象、节奏、口头禅、幽默浓度**。
逐维的判定信号与学术变体侧重见 `references/style-dimensions.md`。

判定结果写入 frontmatter `genre`（`general` 或 `academic`），并据此选模板。模糊时（如带叙事笔法的学术
专栏），按**主导文风**归一类，并在画像里点明混搭成分。

## 输出与存放

- **目录结构**（每个对象一个文件夹）：
  ```
  outputs/lusca-style-distill/{slug}/
    ├── style-dna.md      # 单篇风格画像
    └── author-dna.md     # 多篇合并的作者 DNA（同一作者同一 slug 下）
  ```
- **slug**：单篇取自作者或标题（kebab-case，**不带时间戳**）；多篇取自作者名；同一对象的多次提取**累积到
  同一文件**（除非用户要求新开）
- **frontmatter**：`target`（作者 / 出处）/ `genre`（general / academic）/ `source_articles`（单篇 1、多篇
  N）/ `article_titles`（多篇时列出各篇）/ `sample_scope`（取样范围说明）/ `created_at` / `last_updated` /
  `generator`
- **文末出处块**（遵 CLAUDE.md「文档输出规范」，三行）：
  ```
  > 作者：lusca
  > 版本：lusca-style-distill v1.0.0
  > 出处：https://github.com/yjmm10/lusca-skill/tree/main/skills/lusca-style-distill
  ```
- **段落不硬换行**：遵 CLAUDE.md——正文与列表项写在一行，段间空行分隔，不在句中按列宽折行

## 重要约定

- **每条判断必带原文佐证**：不脑补、不甩无从核对的形容词；特征 + 佐证两段成对出现。
- **可迁移清单要具体可执行**：Do/Don't 写动作不写空话，拿到就能照做。
- **给反例**：写出不属于该风格的样子，防滥用。
- **多篇区分稳定 vs 偶发**：稳定标高置信、偶发标"仅见于某篇"，不混。
- **风格 ≠ 内容**：只管"怎么说"，不评判内容；内容交给 read。
- **文体自动判定、用户明示优先**：按主导文风归类，模糊处点明混搭。
- **不就地改原文**：源文件保持原样，画像独立落盘到输出目录。
- **交付精简**：落盘后只给路径 + 一两句要点（文体判定、签名发现、有几条低置信），**不内联重复展示完整画像**。

---

## 质量底线

- **逐条核对原文佐证**：每条判断都能指回原文某句；指不出的删掉或补证据。
- **可迁移清单可照做**：每条 Do/Don't 是具体动作，不是形容词。
- **文体侧重到位**：学术/技术该重的维度（时态语态 / 术语引用 / claim 校准 / 公式嵌入）没漏；通用该重的
  （人格 / 修辞 / 节奏 / 幽默）没漏。
- **多篇置信度如实**：稳定 / 偶发分清，小样本（1–2 篇）不夸大成"作者 DNA"。
- **取样覆盖全文**：长篇取样含头中尾与风格变化处，不只看开头。
