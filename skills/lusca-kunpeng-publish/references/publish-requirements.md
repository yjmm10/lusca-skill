# publish-requirements — 鲲鹏社区发布要求汇总

## 一、鲲鹏发布要求（权威口径，用户提供，2026-09）

审计以此五条为首要依据，逐条可判合规 / 不合规：

1. **正文不要使用外部链接**：范围 = 发布时贴进编辑器的正文（含文末参考来源节）；frontmatter 属本地元数据、不随发布，其 `sources` 的 URL **保留**，作为正文文字出处的查证底账；正文出处改为**文字标注**（文档名 · 版本/章节，如"《鲲鹏 Hardenous Boot 调优指南》第 2 章"）
2. **不要图片**：零图，含封面图、示意图；mermaid 代码块在平台编辑器不保证渲染（显示源码），架构 / 流程用**文字层次 + 表格**表达
3. **表述专业严谨**：陈述句为主，不用口语、比喻、打趣、反问、绝对化表述；结论可溯源（以文字出处形式）、未验证标 `(uncertain)`；术语准确、首现可配简短白话解释
4. **包含实际操作**：每篇有可执行内容——代码块、命令行、分步操作缺一不可；纯概念文不合规，需补实操环节或重新定位体裁
5. **教程要有实际应用**：教程不止最小示例，收尾须落到真实应用场景（生产配置、性能调优、故障排查等），让读者能迁移到自己业务

## 二、华为计算内容生态基线（明文，华为云社区规范 2022-09）

作为第二层依据，重点是下线红线：

- **AI 痕迹内容下线**：明显 AI 痕迹、语句不通顺、代码错误 → 下线
- **GEO 内容下线**：明显 AI 机器编写、为大模型提供语料；内容未经证实、无意义对比 → 下线
- 不欢迎：抄袭 / 未授权转载 / 翻译不标注、水文（无主题无开头结尾）、排版混乱、广告营销、对友商产品不实抨击、政治政策内容
- 参考性建议（与 §一 冲突时以 §一 为准）：摘要 ≤200 字、小标题分层加序号、列举对比用表格

## 三、官方页面核验提示

- 鲲鹏社区《内容发布规范》页面 JS 渲染、AI 抓不到正文，审计前提醒用户人工核对最新口径：`hikunpeng.com` 开发者博客栏目内置该规范文
- 「AI 生成内容占比 ≤30%」为早前调研口径，未能复核官方原文，按 `(uncertain)` 处理；执行上按"明显 AI 痕迹即有下线风险"的保守标准

## 四、案例投稿通道（案例专区，非博客）

- 流程：按模板编写（Word / Markdown）→ 发 `usecase@huawei.com` → 运营 / 营销 / 品牌 / 法务审 → 多渠道发布
- 模板六段：案例名称、客户简介、项目背景、具体方案介绍、项目价值、其他参考资料
- 特征：价值全部量化（如开发时间 30→20 人天、写带宽 +17%）；同样遵守 §一 五条（案例文字稿无外链无图，数据来自真实项目）
