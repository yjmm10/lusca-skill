# revision-playbook — 改进执行与交付

## 一、AI 可改 vs 必须人工（分界）

### AI 可改（AI 执行，逐条报告改动）

- **去外部链接（仅正文）**：正文全部 URL / markdown 链接改为文字出处（文档名 · 版本/章节）；正文参考来源节保留条目去 URL，frontmatter `sources` 不动（保留 URL 底账）；报告逐条列出替换对照
- **删图**：删除全部图片与图注，上下文引用改指向文字描述；架构 / 流程内容补文字层次 + 表格表达
- **表述严谨化**：口语 / 比喻 / 打趣 / 绝对化逐处改陈述句（注意：这仍是 AI 改写，**不改变**稿件 AI 生成的整体属性，不作为"消除 AI 痕迹"的手段宣传）
- **补实操**：基于正文已有内容补代码块、可执行命令、分步操作（仅限有依据的内容；新写的命令 / 代码标 `(uncertain)` 并列实机待办）
- **补实际应用**：收尾补应用场景节（场景、参数、效果）；超出已验证范围的部分标 `(uncertain)`
- **标题 / 摘要 / 标签**：标题给 2–3 个候选由用户选；摘要 ≤200 字；标签 2–5 个
- 代码技术性修复：修错误 API / 命令，逐条报告；来源补全（文字出处，只增不删）

### 必须人工（列待办清单交用户，AI 不代劳）

- **实机验证**：每条命令 / 每段代码在鲲鹏环境跑通；`(uncertain)` 断言逐条验证或删除；实测数据（性能数字、命令输出）以**文字形式**由作者贴入
- **关键段落亲口重写**：痕迹密度中 / 高的稿件，正文由作者按自己的表达重写（AI 可提供逐段要点提纲辅助，不代写）
- **授权确认**：引用他人内容 / 翻译的授权与标注；转载声明
- **署名与原创声明**：作者署名；平台原创声明功能确认后勾选

## 二、交付物格式

### 审查报告（`<原文件名>.audit.md`）

```markdown
# 合规审查报告：<稿件名>
- 审查日期 / 稿件来源（AI 生成 / 人写 / 混合）/ 痕迹密度分级
## 五条要求核对表
| 要求 | 结论 | 位置 / 说明 |
|------|------|------------|
## 问题清单
| # | 维度 | 位置 | 问题 | 严重度 | 处理方 |
|---|------|------|------|--------|--------|
## AI 已改项（改稿写回后补记）
## 人工待办（可勾选）
- [ ] ...
## 发布风险结论
一句话：可发布 / 改后可发 / 必须人工重写后发
```

### 改稿

- 默认原地写回；报告"AI 已改项"逐条可溯
- 报告与改稿**同时**交付，报告在发布风险结论处如实引用痕迹密度分级

## 三、边界与应答口径

- 用户问"怎么过 AI 检测 / 怎么降低检测率"：如实说明本 skill 不做检测规避；平台规则针对"明显 AI 痕迹、语句不通、代码错误、内容未经证实"——把内容真实化（实机验证 + 自己的数据 + 亲口重写）之后，"过检测"是结果而不是目标
- 用户要求编造实测数据 / 伪造运行结果：拒绝，说明这是下线红线且违反本 skill 事实红线
- 痕迹密度高 + 用户没有实机条件：如实建议"暂不投稿"，列最低可行路径（哪些段必须亲测、哪些数字必须真实采集）
